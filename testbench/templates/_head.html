{#- Shared for every page: participant, public and workspace. One design system. - Tokens and components live in static/admin/app.css: the palette (`ink`, `muted`, `paper`, `card`, `line`, status colours), type (Hanken Grotesk), and the components (`.btn`, `.panel`, `.input`, `.label`, `.t-page` …). Reach for a component before writing a stack of utilities, so a button on a participant page is the same button as in the workspace. - Tailwind's theme (static/admin/tw.js, and tailwind.config.js for LOCAL_ASSETS=1) maps the same variables, so `bg-card text-ink` flips with the theme and `bg-brand` follows a study's own colour. Hand-writing `dark:` on every element is how you end up with a dark card whose heading is invisible; reach for it only for a genuine one-off. - A study's colour is set on by `html_attrs()` in _brand.html; pages without a study use the neutral accent, which flips to a light one in the dark theme. -#} {#- Set the theme class before the first paint, or a dark-theme visitor gets a white flash on every page load. This has to be inline and before the stylesheet; a deferred script is too late. An explicit choice wins; otherwise follow the operating system. -#} {#- The app's mark.
